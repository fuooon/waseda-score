# ⚾ 早稲田式スコアブック

少年野球向けの早稲田式スコア記録Webアプリです。
試合のスコアをスマホから簡単に記録し、画像としてLINEグループなどに共有できます。
スコアの付け方に詳しくない保護者でも、記録が正しいかを自分で確かめられることを目指しています。

## 主な機能

- **試合設定** — 日付・チーム名（空欄でも可）・球場・イニング数（5／6／7／9回）・DH制・タイブレーク（開始回と置きランナー）
- **メンバー管理** — チームごとに選手の名前・背番号・打ち方・主なポジションを登録。相手チームも登録できます
- **スタメン登録** — 先攻・後攻の打順（DH制でも9人）、守備位置、先発投手。名簿から選ぶと背番号・打ち方・守備位置が自動で入り、選手や守備位置の重なりは警告で知らせます。入力は1つ変えるごとに保存されるので、途中で画面を閉じても続きから入力できます
- **スコア記録** — 早稲田式の記号で打席結果をタップ入力。守備番号はボタンで入力（キーボードは出ません）。走者の進塁・打点の提案・併殺の走者選択も入力画面で案内します
- **状況表示** — いまの回、アウト数（●●○）、塁上の走者、次の打者をスコアシートの上に表示。「次: ○番」をタップするとその打者の入力が開きます
- **読み上げ（記録の説明文）** — 各マスの内容を「4番 田中：ショートゴロ（6-3）でアウト【1アウト目】」のような文章で表示し、入力が実際のプレーと合っているか確かめられます
- **記録チェック** — 打者数＝得点＋残塁＋アウト、打点と得点、打順の抜け、アウト数などを自動で照合し、おかしいところを分かりやすい言葉で知らせます（ルールの詳細は [docs/scoring-rules.md](docs/scoring-rules.md)）
- **スタメン編集・選手交代** — 試合中でも ⚙️試合設定 →「スタメン編集」で名前や守備位置の入力ミスを直せます。代打・代走・守備交代は 🔄 から記録・取り消しできます
- **過去の試合** — 「新しい試合」を始めると、それまでの試合は自動で保存されます（最大30試合）。あとから開いて続きを記録したり、画像を作り直したりできます
- **バックアップ** — チーム・選手・記録中の試合・過去の試合を1つのJSONファイルに保存し、別の端末やブラウザのデータが消えたあとに復元できます
- **記号ガイド** — スコアのつけ方の基本と、アプリで使う記号の一覧（スコアシートと同じ描き方）をアプリ内で確認
- **画像エクスポート** — フルスコアシート or スコアボードを画像にしてダウンロード・共有

データはすべて端末のブラウザ（localStorage）に保存されます。サーバーには送信しません。
ブラウザのデータを消すと記録も消えるので、ときどき「📚 過去の試合」の画面からバックアップを保存してください。

## 技術スタック

| 項目 | 技術 |
|------|------|
| ビルドツール | [Vite](https://vitejs.dev/) |
| テスト | [Vitest](https://vitest.dev/) |
| 画像エクスポート | [html2canvas](https://html2canvas.hertzen.com/) |
| フォント | Noto Sans JP / M PLUS 1 (Google Fonts) |
| フレームワーク | なし（Vanilla JS） |

## セットアップ

```bash
# 依存パッケージのインストール
npm install

# 開発サーバーの起動
npm run dev
```

開発サーバーが起動したら、表示されるURL（通常 `http://localhost:5173/waseda-score/`）をブラウザで開いてください。

## テスト

```bash
npm test
```

採点ロジック（得点・アウト・残塁・打順・試合終了・整合性チェック C01〜C19）、記録の説明文、マスの描画、入力画面のロジック、スタメンの警告、過去の試合とバックアップをテストしています。
採点ルールは [docs/scoring-rules.md](docs/scoring-rules.md) にまとめています。ルールを変えるときは、この文書とテストを一緒に直してください。

## ビルド・デプロイ

```bash
# 本番ビルド
npm run build

# ビルド結果のプレビュー
npm run preview
```

`master` ブランチに push すると、GitHub Actions（`.github/workflows/deploy.yml`）がテスト → ビルド → GitHub Pages へのデプロイを行います。
Actions の画面から手動で実行することもできます（workflow_dispatch）。プルリクエストではテストとビルドだけを行います。

## プロジェクト構成

```
waseda-score/
├── index.html            # メインHTML（各ページとモーダル）
├── package.json
├── vite.config.js
├── docs/
│   └── scoring-rules.md  # 採点ルールと整合性チェックの仕様
├── tests/                # Vitest のテスト
└── src/
    ├── main.js           # エントリーポイント・ページ遷移・メニュー
    ├── rules.js          # 野球のルール定数（打撃結果・走塁イベント・守備位置）
    ├── scoring.js        # 採点エンジン（得点・アウト・残塁・打順・試合終了・チェック）
    ├── data.js           # データモデルと保存（localStorage）
    ├── util.js           # 共通処理（エスケープ・日付・トースト）
    ├── describe.js       # 記録を文章にする（読み上げ）
    ├── cell-render.js    # スコアシートのマスの描画
    ├── help.js           # 記号ガイド・スコアのつけ方
    ├── game-setup.js     # 試合設定画面
    ├── lineup.js         # スタメン登録・編集画面
    ├── team-members.js   # メンバー管理画面
    ├── history.js        # 過去の試合・バックアップ
    ├── scoresheet.js     # スコアシート（状況表示・記録チェック・選手交代・試合設定）
    ├── scoreboard.js     # スコアボード表示
    ├── score-input.js    # 打席結果の入力パネル
    ├── export.js         # 画像エクスポート
    ├── style.css         # 共通スタイル
    └── styles/           # 画面ごとのスタイル
```
